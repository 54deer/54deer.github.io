    mongoDB 基础知识

    作者 54deer · 日期 2026-10-01

    简介

    MongoDB是文档数据库（面向文档的可操作数据库），是作为现代应用程序关系数据库的替代方案而全新构建的。与关系数据库不同， MongoDB允许开发者存储丰富的类似JSON的文档

    存储结构对比

    MySQL mongoDB 说明
    数据库 数据库 对应磁盘的一个目录
    表 集合 一组数据单位的集合,MySQL表要求字段固定，而集合自由无限制，
    数据行 文档 存储数据的基本单位

    事务

    • MongoDB支持多文档事务，允许您将多个读取和写入操作作为单个全有或全无事件运行。

    高可用性

    • MongoDB 的内置复制机制提供自动故障转移、数据冗余和更高的读取容量

    水平缩放

    • MongoDB通过一种称为分片的技术本身支持水平扩展。

    文档

    MongoDB将数据记录存储为BSON文档(BSON是JSON文档的二进制表示形式，包含比JSON更多的数据类型)，文档由成对的字段和字段值组成

    • 字段是字符串类型
    • 字段值可以是任何一种 BSON 数据类型，包括其他文档、数组和文档数组

    字段名称限制

    1. 字段名称 _id 保留用作主键；它的值在集合中必须是唯一的、不可变的，并且可以是除数组或正则表达式之外的任何类型。如果 _id 包含子字段，则子字段名称不能以 ($) 符号开头。 字段名称不能包含 null 字符。
    2. 允许存储包含点 (.) 和美元符号 ($) 的字段名称。
    3. 每个字段名称在文档中必须是唯一的。 不得存储具有重复字段的文档，MongoDB 查询语言不支持具有重复字段字段的文档。

    文档大小限制

    • BSON文档大小的上限为 16 MB
    • 最大文档大小有助于确保单个文档不会使用过多的 RAM，或者传输过程中不会使用过多的带宽

    查询中的字段顺序

    • 比较文档时，字段排序很重要 ——{a: 1, b: 1} 不等于 {b: 1, a: 1}，为了高效执行查询，查询引擎可能会在查询处理过程中对字段重新排序，字段重新排序可能发生在中间结果以及通过查询返回的最终结果中

    写入操作中的字段顺序

    • 对于写入操作，MongoDB 会保留文档字段的顺序，包含字段名称 renaming 的更新可能会导致文档中的字段重新排序

    _id 字段

    • _id 字段始终是文档中的第一个字段
    • 集合中的每个文档都需要一个唯一的_id字段作为主键。如果插入的文档省略了 _id字段，则MongoDB驱动程序会自动为 _id字段生成 ObjectId。
    • 默认情况下，MongoDB 在创建集合期间会在 _id 字段上创建唯一索引，在时间序列集合中，文档不需要唯一的_id字段，因为MongoDB不会在_id 字段上创建索引
    • 如果 _id 包含子字段，则子字段名称不能以 ($) 符号开头
    • _id 字段可以包含任何 BSON 数据类型的值（数组、正则表达式或未定义类型除外）。

    数据库和集合

    • MongoDB 将数据记录作为文档（BSON文档）存储在集合中。数据库包含一个或多个集合
    • MongoDB 将文档存储在集合中。集合类似于关系数据库中的表

    use myDB切换数据库，不存在也可切换，没写数据前不会创建

    db.myNewCollection1.insertOne( { x: 1 } )插入同时创建数据库myNewDB 和集合myNewCollection1（如果尚不存在）

    集合分配了一个不可变的 UUID 在所有副本集成员和分片中保持一致。要检索集合的 UUID，可运行 listCollections 命令或 db.getCollectionInfos() 方法。
